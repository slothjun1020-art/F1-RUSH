# F1 Rush

친구와 실시간으로 5바퀴를 먼저 완주하는 사람이 이기는 탑다운 F1 스타일 레이싱 웹게임입니다.
실존 서킷 10곳(모나코, 실버스톤, 몬차, 스즈카, 스파, 인터라고스, 앨버트 파크, 마리나 베이, COTA, 레드불 링)을 단순화한 트랙으로 즐길 수 있습니다.

## 실행

```bash
npm install
npm start          # http://localhost:3000  (PORT 환경변수로 변경)
```

1. 브라우저에서 닉네임을 입력하고 **방 만들기**를 누릅니다.
2. 화면의 **방 코드**(또는 초대 링크)를 친구에게 알려 줍니다. 친구는 같은 주소에서 코드를 입력해 입장합니다.
3. 방장이 서킷을 고르고, 다른 플레이어가 **준비**를 누르면 방장이 **출발!**을 누릅니다.

조작: `↑`/`W` 가속, `↓`/`S`/Space 브레이크, `←→`/`AD` 조향, `R` 리셋(차를 트랙 위로 되돌리고 정지, 랩 기록은 그대로).
화면 왼쪽 아래 **↺ 리셋** 버튼도 같은 기능입니다. 기어 모드가 켜진 방에서는 `3`(다운시프트)/`4`(업시프트)로 변속합니다.

### 차량 충돌과 기어 모드 (로비에서 방장이 켜고 끔)
로비 화면 서킷 선택 아래 두 토글 버튼으로 방장이 설정합니다. 게스트에게는 현재 켜짐/꺼짐 상태만 보입니다.

- **🚗💥 차량 충돌**: 켜면 차끼리 파손 없이 범퍼카처럼 서로 밀어냅니다(정면으로 부딪힐수록 속도를 더 잃음). 끄면 지금처럼 서로 통과하는 고스트 방식입니다. 네트워크 지연 때문에 다소 어색할 수 있어 기본값은 꺼짐입니다.
- **🔧 기어 모드**: 켜면 8단 반자동 시퀀셜 기어로 바뀝니다(단수별 최고 속도는 `shared/physics.js`의 `GEAR_SPEEDS_KMH`에서 한 곳으로 관리: 20/60/100/140/180/220/260/300 km/h). 변속(`3`/`4`)은 **언제나 자유롭습니다** — 막히지 않습니다. 대신 기어와 속도가 안 맞으면 물리적으로 손해를 봅니다: 속도가 낮은데 높은 단이면 가속이 약해지고(엔진이 눌리는 느낌), 속도가 그 단의 최고 속도보다 높으면(예: 고속에서 낮은 단으로 변속) 서서히 그 단의 최고 속도로 수렴하도록 부드럽게 감속합니다(엔진 브레이크, `CAR.gearOverBrakeRate`로 세기 조절). HUD의 기어 숫자는 너무 빠르면 금색(`.shift`), 너무 느리면 하늘색(`.lug`)으로 알려주기만 하고 조작은 막지 않습니다. 끄면 지금처럼 자동 변속(기어를 신경 쓸 필요 없음)입니다.
  기어 모드가 켜진 방에서 레이스가 시작되면(나중에 들어온 사람 포함, 그 방에서 처음 레이스할 때 한 번) 조작법 안내창이 뜹니다. 확인 버튼이나 `Esc`로 닫히고, 열려 있는 동안 주행 키는 무시됩니다.

### 화면: 3D 추격 카메라 / 2D 탑다운
기본은 **3D 3인칭 추격 화면**(로우폴리)입니다. `V` 키로 기존 **2D 탑다운 화면**과 언제든 전환할 수 있고 (화면에 버튼은 없습니다),
주소 뒤에 `?view=2d`를 붙이면 2D로 시작합니다. 브라우저가 WebGL을 지원하지 않으면 자동으로 2D로 전환됩니다.

### 나가기
왼쪽 아래 **✕ 나가기** 버튼(카운트다운·레이스 중)을 누르면 "정말 나갈까요? 나가면 이번 기록이 사라져요" 확인창이 뜨고, 확인하면 방을 나가 시작 화면으로 돌아갑니다.
키보드 포커스를 가져가지 않아 브레이크(Space)를 눌러도 실수로 눌리지 않고, 확인창은 `Esc`로 닫을 수 있습니다. 결과 화면에서는 확인 없이 바로 나갈 수 있습니다.
- 남은 사람들에게는 나간 사람이 **DNF(기록 없음)**로 표시되고(순위판과 결과 화면), 이미 완주한 사람이 나가면 기록이 그대로 남습니다.
- 방장이 나가면 방장 권한이 다음 사람에게 넘어갑니다. 혼자 남아도 레이스는 계속되고 결과 화면이 정상적으로 나옵니다.
- 연결이 끊기거나 브라우저를 닫아도 똑같이 처리됩니다.
3D가 느린 PC에서는 프레임이 떨어지면 자동으로 그림자/해상도를 낮춥니다 (`?q=0..3`으로 시작 품질을 직접 지정할 수도 있어요).

친구가 다른 네트워크에서 접속하려면 서버를 외부에서 접근 가능하게 해야 합니다 (터널 또는 호스팅 배포). WebSocket을 지원하는 곳이어야 합니다.

### 임시 공개 주소 (Cloudflare 퀵 터널, 가입 불필요)
```bash
winget install Cloudflare.cloudflared      # 한 번만
npm start                                  # 터미널 1: 게임 서버 (http://localhost:3000)
cloudflared tunnel --url http://localhost:3000   # 터미널 2: 출력에 나오는 https://....trycloudflare.com 이 친구에게 보낼 주소
node scripts/tunnel-check.mjs https://....trycloudflare.com   # (선택) 그 주소로 실제 접속이 되는지 확인
```
- 주소는 터널을 켤 때마다 **새로 생기는 임의의 주소**이고, `cloudflared` 창을 닫거나 서버/PC를 끄면 사라집니다. 다음에 다시 켜면 다른 주소가 나옵니다.
- 게임 서버(`npm start`)도 켜져 있어야 합니다. 방장이 방을 만들고 친구가 `주소/?room=코드` 초대 링크로 들어옵니다.
- 이 주소를 아는 사람은 누구나 접속할 수 있으니, 친구에게만 보내세요.

## 트랙 크기 / 속도 조절

차 크기는 그대로 두고 **트랙의 크기만 `shared/scale.js` 한 곳의 배율로** 바꿉니다 (서버와 브라우저가 같은 파일을 씁니다).

| 값 | 기본 | 의미 |
|---|---|---|
| `SCALE.length` | 2.4 | 한 바퀴 길이 배율 |
| `SCALE.width` | 2.25 | 도로 폭 배율 |
| `SCALE.speedTrim` | 0.72 | 차 속도 미세 조정. 클수록 빠른 차 = 짧은 랩 |

길이 배율에 맞춰 최고 속도와 가속이 자동으로 따라가고(`SPEED_SCALE`), 샘플 간격(랩 판정 "체크포인트"), 연석, 가드레일 위치,
나무 개수, 언덕, 출발선/게이트, 카메라와 안개 거리, HUD 속도 표시가 함께 조정됩니다. 미니맵은 원래부터 트랙에 맞춰 자동으로 맞춰집니다.
값을 바꾼 뒤에는 서버를 다시 시작하고 `npm test`를 돌려 보세요 (봇 한 바퀴 시간이 15~45초인지, 트랙끼리 안 겹치는지도 검사합니다).

최고 속도는 **300km/h**(`shared/physics.js`의 `GEAR_SPEEDS_KMH` 맨 끝 값)이고, 기어 모드가 꺼져 있어도 동일합니다. 속도가 오를수록 조향 감도가 서서히 줄어
최고 속도에서는 저속 대비 약 40%가 됩니다.

브레이크는 처음에는 약하게 걸리고 오래 누를수록 강해지며(약 2.4초에 걸쳐), 떼면 다시 약해집니다. 가속 페달을 뗐을 때도 곧바로 코스팅 저항이 걸리지 않고
약 1.1초에 걸쳐 서서히 세지므로(`coastRamp`), 뗀 순간 속도가 뚝 끊기지 않습니다. 300km/h로 최고 속도가 오르면서 두 값 모두 예전보다 부드럽게 다시 조정했습니다.
관련 값은 `shared/physics.js`의 `CAR`에 있습니다.

## 개발

```bash
npm test           # 단위/통합 테스트 (트랙 기하, 봇 주행, 서버 레이스 판정, WebSocket)
npm run e2e        # 실제 Chrome 두 개로 로비 → 3D 레이스 → 리셋/화면 전환 → 결과 전체 흐름 (Chrome 필요, CHROME_PATH로 경로 지정 가능)
npm run e2e:leave      # 나가기: 확인창, DNF 표시, 방장 이전, 혼자 남아 완주, 결과 화면 (2D 화면으로 빠르게 실행)
npm run e2e:features   # 로비 토글, 기어 모드 안내창·자유 변속·HUD 표시·엔진 브레이크, 충돌 밀림 (2D 화면으로 빠르게 실행)
npm run e2e:fallback   # WebGL이 없는 브라우저에서 2D로 자동 전환되는지 확인
node scripts/shots3d.mjs [트랙id] [품질 0-3]   # 3D 화면 스크린샷 (예: monaco, suzuka)
```

headless Chrome은 WebGL을 소프트웨어로 그려서 느립니다. e2e는 이 때문에 작은 화면과 낮은 품질로 실행하며, 실제 PC(GPU)에서는 훨씬 부드럽습니다.

`/preview.html`에서 10개 트랙 모양을 한눈에 볼 수 있습니다.

## 구조

| 경로 | 역할 |
|---|---|
| `shared/` | 서버와 브라우저가 같이 쓰는 로직: 트랙 정의(`tracks.js`), 기하(`track-geom.js`), 주행 물리·기어 테이블(`physics.js`), 랩 판정(`race.js`), 차량 충돌(`collision.js`), 봇(`bot.js`) |
| `server/` | Express + `ws`. `rooms.js`는 방/레이스 로직(네트워크와 분리, 시계 주입 가능) |
| `public/` | 브라우저 클라이언트: 로비/HUD(`main.js`), 레이스 루프·HUD(`game.js`, 그리기는 렌더러에 위임) |
| `public/view2d.js`, `render.js` | 기존 2D 탑다운 렌더러 |
| `public/view3d.js`, `car3d.js`, `track3d.js` | 3D 추격 카메라 렌더러(Three.js), 로우폴리 차량, 도로/연석/가드레일/언덕 지오메트리(순수 함수라 테스트 가능) |
| `public/interp.js` | 다른 플레이어 차 보간: 적응형 지연 버퍼, 예측(extrapolation), 튐 방지 보정 (순수 함수, 테스트 가능) |

## 네트워크 방식

각자 자기 차를 브라우저에서 시뮬레이션하고 위치를 초당 32회(`shared/protocol.js`의 `SEND_HZ`) 서버로 보냅니다. 서버는 위치를 검증해 체크포인트 없이도 "트랙을 따라 실제로 이동한 거리"로 랩을 세고(역주행, 지름길, 순간이동은 진행으로 인정하지 않음), 서버 시각 기준으로 완주 순위와 기록을 확정한 뒤 초당 30회(`SNAP_HZ`) 모든 차의 위치를 다시 방 전체에 알립니다. 메시지는 좌표를 정수 단위, 각도를 소수 2자리로 줄여 빈도가 오른 만큼 크기가 커지지 않게 했습니다. 서버는 TCP Nagle 알고리즘(`setNoDelay`)과 WebSocket 압축(`permessage-deflate`)을 꺼서 작은 메시지가 불필요하게 지연되지 않게 합니다.

다른 플레이어의 차는 고정 지연이 아니라 **적응형 보간 버퍼**로 그립니다(`public/interp.js`). 스냅샷이 얼마나 불규칙하게 도착하는지(지터)를 계속 측정해서, 인터넷 상태가 나빠지면 버퍼를 늘리고(최대 350ms) 안정되면 다시 줄입니다(최소 60ms 근처). 데이터가 잠깐 끊기면 마지막 속도·방향으로 최대 150ms까지만 짧게 예측해서 움직이고, 끊겼던 데이터가 다시 올 때 위치가 크게 벌어져 있으면 순간이동하지 않고 짧게(약 0.1초) 부드럽게 따라잡습니다. 평소의 작은 움직임에는 이 보정이 끼어들지 않아 지연이 늘지 않습니다.

주소 뒤에 `?debug=1`을 붙이면 화면 위쪽 가운데에 작게 핑(ms)과 프레임 수(FPS)가 표시됩니다.
